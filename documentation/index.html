Documentation

Everything you need to open, edit and ship Qevora AI SaaS UI. No prior build-tool knowledge is required — the template works as plain HTML, and the optional build script simply saves you copy-paste work.

Design system Browse components

What you received

A complete static admin template: 84 HTML pages, a component library with copy-ready snippets, light and dark themes, RTL support and every library vendored locally — the template never calls a CDN at runtime.

Bootstrap 5.3.3 Bootstrap Icons 1.11.3 Chart.js 4.4.3 Inter (self-hosted) Light + dark RTL ready

Version

1.0.0 · October 2026

Verified in Chrome, Edge, Firefox and Safari (last two major versions).

1. Quick start

  1. Unzip the package anywhere on your computer.
  2. Double-click index.html — the dashboard opens in your browser immediately.
  3. Use the search box in the component pages, toggle the theme from the header, and explore.
  4. To edit, open the HTML file you want in any code editor (VS Code, Notepad++, Sublime Text).
Do you need a local server? No. Every path in the template is relative, so opening the files directly from disk works. A local server is only handy if you want to test on a phone: run python3 -m http.server 5500 inside the folder and open http://localhost:5500.
This download needs no build step Everything you were given is finished HTML: open it, edit it, upload it. The src/ fragments and the tools/ scripts belong to the separate developer source package; section 5 is the only part of this guide that uses them, and it says so at the top.

3. Customising the template

Almost every visual decision lives in one CSS variable block at the top of assets/css/style.css. Change the value there and the whole template follows — buttons, charts, badges, the sidebar and dark mode.

Brand colour

:root {
  --q-primary: #4f46e5;
  --q-primary-rgb: 79, 70, 229;   /* keep in sync */
  --q-primary-hover: #4338ca;
  --q-primary-soft: #eef0ff;
}

Layout measurements

:root {
  --q-sidebar-width: 268px;
  --q-sidebar-width-compact: 78px;
  --q-header-height: 66px;
  --q-content-max: 1560px;
}
  • Radius: --q-radius-xs to --q-radius-xl drive every rounded corner, including cards and inputs.
  • Fonts: Inter is self-hosted in assets/fonts/inter/. Swap the @font-face block in assets/css/fonts.css and the --q-font-sans token to change it.
  • Logo: replace assets/images/logo/logo.svg and logo-white.svg (used on the auth pages), and favicon.svg for the browser tab.
  • Sidebar menu: edit the <aside class="q-sidebar"> block at the top of each page — the markup is identical in every file, so one find-and-replace updates all of them. If you also have the developer source package, edit src/nav.mjs once and run the builder instead (section 5).
  • Dark mode: toggle with any [data-theme-toggle] button — the choice is stored under the qevora-theme key in localStorage.
  • RTL: click the translate icon in the header (or add dir="rtl" to the <html> tag) — the sidebar script swaps in bootstrap.rtl.min.css automatically.

5. Optional developer source package

Developer package only The commands on this page read src/ and tools/, which are not part of the standard buyer download. If your package has no src/ folder, skip this section — every other section works on the finished HTML files alone.

Editing 84 files every time the header changes is tedious, so the developer package adds a tiny builder. It stitches the shell partials and each page body into the final HTML files. It has no dependencies and needs Node 18 or newer. 

node tools/build.mjs             # write every page in src/pages.mjs
node tools/build.mjs --check     # validate only: report missing bodies and dead links
node tools/audit.mjs             # 21 static QA checks per page, plus light/dark theme contrast
node tools/audit.mjs --part ai   # audit one section at a time
npm i --no-save jsdom            # one-off, for the optional runtime check
node tools/smoke.mjs             # run every page and click key controls: console errors, missing assets

How a page is assembled

Each entry in src/pages.mjs declares the output path, the page title and description, the breadcrumb trail, an optional layout (app for the dashboard shell, blank for auth and utility pages) and any extra scripts. The builder then replaces these tokens inside the partials and the body:

TokenReplaced with
{{META_TITLE}}The page <title>
{{META_DESC}}The meta description
{{DEPTH}}Relative prefix (../) so every asset path stays correct at any folder depth
{{NAV}}The full sidebar menu, built from src/nav.mjs
{{BREADCRUMB}}The page-header breadcrumb
{{CONTENT}}The body file from src/pages/
{{PAGE_SCRIPTS}}Extra scripts such as Chart.js for chart pages
{{HEAD_EXTRA}}Optional extra tags for the <head>

How the component pages are built

Every demo block on a component page carries four panes: Preview, HTML, CSS and JS. You author the preview and the HTML sample; the builder writes the other two from what actually ships — the CSS rules are lifted out of assets/css/style.css and components.css for the exact classes used in that block, and the JS pane lists the hooks the block relies on (Bootstrap data attributes are reported as "no custom script required"). That way the samples can never drift from the code.

Adding a new page in four steps

  1. Create the body file, for example src/pages/pages/roadmap.html.
  2. Add an entry to src/pages.mjs with its out path, metadata and breadcrumb.
  3. Add the menu link to src/nav.mjs.
  4. Run node tools/build.mjs — the new page appears with the correct title, breadcrumb and navigation in every other page.
  5. Run node tools/audit.mjs — it checks headings, labels, ids, anchors, class names, data hooks, chart wiring, link targets and the four-pane demo contract before you ship, and it measures the light/dark contrast of the palette tokens (tooltips, cards, toasts) once for the whole theme.
If you edit the HTML directly, stop using the builder The build script overwrites the generated files at the repository root. Either work in src/ and rebuild, or edit the generated HTML and ignore src/ — mixing both will lose work.

6. Accessibility & browser support

  • Skip links, landmarks, labelled forms and aria-* states are included on every page.
  • Icon-only controls always carry an aria-label; decorative icons use aria-hidden="true".
  • Colour contrast targets WCAG AA in both themes — the dark palette re-tunes the brand colour rather than only inverting it.
  • Animated counters respect prefers-reduced-motion and print the final value immediately.
  • Tables, pagination and cards are keyboard reachable; the mobile drawer closes on Esc.
  • Tested in Chrome, Edge, Firefox and Safari (last two major versions) plus iOS Safari and Chrome on Android.
  • Every overlay fits the narrowest phone: the board filter opens anchored to its button, keeps its own close button in the header, scrolls its groups and pins its summary and Clear — and it only exists while it is open. The header holds one even row of 40px controls below 768px, with the profile as a circle there, because the name and role are hidden and a pill around a circle reads as an oval.
