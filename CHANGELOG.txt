FEATURES

  · Light and dark themes, saved in localStorage, following the system
    preference by default.
  · Full RTL support: logical CSS properties plus an RTL stylesheet and a
    runtime Bootstrap RTL swap.
  · Responsive down to 375 px: collapsible sidebar, off-canvas drawer,
    responsive tables and card grids.
  · Component pages with Preview and HTML tabs, syntax highlighting and copy
    buttons.
  · All libraries vendored locally — no CDN requests at runtime.
  · Relative asset paths only, so the template works from any folder or
    subdirectory.
  · Optional zero-dependency build script (Node 18+) that assembles pages
    from shared partials.
  · Accessibility pass: landmarks, skip links, labelled controls, aria
    states, reduced-motion support, WCAG AA colour targets.

COMPONENT DEMOS — FOUR PANES

  · Every demo block on the 31 UI kit pages now offers Preview / HTML / CSS / JS
    tabs, each with its own copy button (86 blocks in total).
  · The CSS sample is generated at build time: the real rules for the classes used
    in that block are lifted from assets/css/style.css and components.css, and
    classes that come from stock Bootstrap are listed instead of pasted.
  · The JS sample is generated too: it reports the hooks that block actually uses
    — a short API snippet for Qevora's own behaviour, or a clear "no custom
    JavaScript required" note where Bootstrap's data API does the work.
  · components.js gained dependency-free CSS and JavaScript tokenisers, so all
    four panes are highlighted with the same tok-* palette.
  · tools/demo-samples.mjs holds the generator; tools/audit.mjs gained a
    four-pane contract check (86 blocks verified).

HOSTING

  · tools/build.mjs mirrors utility/404.html to the repository root as 404.html
    (root-relative paths, robots noindex) because GitHub Pages serves /404.html
    from the site root. 82 HTML files ship: 81 pages plus that hosting fallback.

QUALITY TOOLING

  · tools/audit.mjs — static QA gate that runs 17 checks over all 82 generated
    pages: document head, duplicate ids, anchor targets, aria/label references,
    image alt text, accessible names on buttons and icon links, form labels,
    class existence against the shipped stylesheets, data-hook coverage,
    chart registry and script wiring, heading outline, tag balance, paragraph
    nesting, interactive nesting, placeholder markers and the four-pane demo
    contract.
      node tools/audit.mjs            report
      node tools/audit.mjs --part ai  audit one section
      node tools/audit.mjs --strict   non-zero exit when anything is found

FIXES DURING DEVELOPMENT

  Shell — collapsed sidebar
    · The 78px icon rail used to hold both the brand mark and the inline
      collapse button, so the two overflowed the rail and the logo was clipped
      against the left edge. The rail now centres the mark on its own and the
      inline button steps aside: the header button collapses and expands the
      sidebar (it is now labelled "Expand navigation" / "Collapse navigation"
      and swaps to a chevron while collapsed).
    · Compact labels were hidden with display:none, which stripped the
      accessible name from every icon-only link and left the fly-out submenus
      showing empty rows. Labels are clipped instead of removed, the submenu
      popovers show their text again, and each rail icon gets a tooltip on
      hover or focus.
    · Both sidebar togglers now report aria-expanded together, and tooltip
      instances are created through getOrCreateInstance so no duplicate
      Bootstrap instance is ever registered.

  Core and design system
    · Four classes used by the pages were never defined in CSS: .min-w-0 (used
      on 71 pages for header and sidebar truncation), .fw-400, .fw-700 and
      .bg-accent. All four are now shipped as utilities.
    · .kanban__col-body — the drag & drop target handled by components.js —
      had no styling; it now has a minimum height so empty columns stay usable.

  Pages
    · Product details and transactions rendered a chart canvas but did not load
      Chart.js, so the widgets would have stayed blank; both now load
      CHART_SCRIPTS.
    · The AI chat rating button had no accessible name; it gained an aria-label
      and a matching thumbs-down action, and decorative icons are now
      aria-hidden.
    · The content generator's reference-material <label for> pointed at an id
      that did not exist; the hidden file input now carries that id.
    · The dropdown menu group label was an <h6>, which skipped heading levels;
      it is a standard list item now.
    · The typography preview rendered a second <h1> beside the page title; the
      sample uses the .h1 utility and the printed sample matches the preview.
    · The rich tooltip example carried raw tags inside a title attribute; it is
      escaped and uses data-bs-title.

  Earlier fixes
    · Corrected the Bootstrap Icons font path in the shared <head> partial.
    · Fixed asset depth on the AI image generator page.
    · Aligned the AI overview "tokens used" counter with its formatted value.
    · Replaced an invalid sticky utility on the FAQ page.
    · Corrected table row links and a stale copy-button target in the UI kit.
    · Registered the chat script only on the two chat pages and the chart
      script only on pages that render charts.
