FEATURES

  · Light and dark themes, saved in localStorage, following the system
    preference by default.
  · Full RTL support: logical CSS properties plus an RTL stylesheet and a
    runtime Bootstrap RTL swap.
  · Responsive down to 375 px: collapsible sidebar, off-canvas drawer,
    responsive tables and card grids.
  · Component pages with Preview and HTML tabs, syntax highlighting and copy
    buttons.
  · All libraries vendored locally — no CDN requests at runtime.
  · Relative asset paths only, so the template works from any folder or
    subdirectory.
  · Optional zero-dependency build script (Node 18+) that assembles pages
    from shared partials.
  · Accessibility pass: landmarks, skip links, labelled controls, aria
    states, reduced-motion support, WCAG AA colour targets.

QUALITY TOOLING

  · tools/check-add-card.mjs — regression check for the "+ New …" controls and
    the "just added" highlight (projects grid columns, numbering, kanban
    counters, calendar and report placement). Needs jsdom.

  · tools/check-states.mjs — interaction-state check. Resolves what a filled
    control actually shows in each state (active pill, active pill hover) for
    both palettes by reading the shipped stylesheets in load order and applying
    the cascade itself — the one thing jsdom cannot do for :hover. Fails if a
    label drops under 4.5:1, if a hover rule repaints the active pill, if a
    .form-select loses the padding its caret needs, or if a badge stops being
    centred in a stretched row. 10 checks.

  · tools/check-controls.mjs — "every click answers" check. Clicks the
    dashboard row actions (message dialog, options menu, copy email, remove
    with undo), the chat conversation menu and list, a tooltip-only button and
    the auth legal links, and fails if a click leaves the page silent.
    Needs jsdom.

  · tools/check-dropdowns.mjs — regression check for every dropdown and pick
    group in the template (one selected item only, the button shows the current
    choice, icons kept, aria-current / aria-pressed, locked items refused) plus a
    sweep of all eight pages that carry pick controls. Needs jsdom.

  · tools/audit.mjs — static QA gate: 19 checks over all 82 generated
    pages: document head, duplicate ids, anchor targets, aria/label references,
    image alt text, accessible names on buttons and icon links, form labels,
    class existence against the shipped stylesheets, data-hook coverage,
    chart registry and script wiring, heading outline, tag balance, paragraph
    nesting, interactive nesting, placeholder markers and the four-pane demo
    contract.

FIXES DURING DEVELOPMENT

  Demo interactions — the buttons and forms now work
    · The template ships a small client-side layer (assets/js/demo-ui.js) so no
      control is a dead end, and pages/leads.html is the reference: "+ Add lead"
      opens a real dialog with validation, saving appends the row (badge,
      avatar, money column and all), the row's view and edit buttons open that
      record, delete asks first and offers an undo, and the status and source
      selects, the live search, the column picker and the pagination all work
      together while the "x of y" counters follow every change.
    · The layer is driven by data attributes and documented under
      documentation/index.html → 4. JavaScript reference: data-demo-open,
      data-demo-form, data-demo-field, data-slot, data-slot-badge,
      data-slot-avatar, data-demo-delete, data-demo-filter, data-demo-count,
      data-demo-column and data-demo-load. Record values live on the row itself
      (data-lead-name, data-lead-status …), so connecting a real API means
      replacing the handlers, not the markup.
    · List pages filter for real: the status pills on invoices and orders are
      chip groups driven by the same engine as the selects (data-demo-chips on
      the group, data-demo-chip on each button, data-demo-chip-field when a chip
      filters on a different column), and the rows carry their record values
      (data-invoice-status …) for the filters to read.
    · Any control that still has no handler answers with a toast that names it —
      and a control inside a component demo says that it is a style demo —
      instead of appearing to do nothing.
    · The runtime smoke test clicks through the new flows on every run, and the
      audit learned two things: a wrapping <label> labels a control that has no
      id, and data-<record>-<field> attributes are valid on any table that
      declares data-demo-record.

    · Every list page is a real list now, not a picture of one. Invoices,
      orders, payments, products, subscriptions, tasks, team, transactions and
      activity each carry their record values on the rows, so the toolbar
      filters (gateway, category, status, plan, role, browser, date range), the
      live search, the generated pager, the "Showing x of y" footer and the KPI
      tiles all read the same five or six rows and can never disagree with them.
    · Create, edit and delete work from anywhere: "New invoice", "Record
      payment", "Add product", "New subscription", "New task", "Invite member"
      and the rest open the shared dialog, which builds its fields from the
      table (text, number or a short list of choices) and writes the row back,
      and every row gained an edit and a delete button beside its existing
      actions. A record added while a filter is active clears that filter, jumps
      to page one and flashes, so it is never invisible.
    · Export is real: the CSV buttons write a file from the rows on screen (a
      download icon inside a row exports just that row), the export buttons on
      cards work off the table inside the card, and the KPI tiles are computed
      from the same data (sum of paid invoices, captured payments, MRR, active
      products, open tasks …).
    · A new row keeps the shape of the table: it is cloned from the first row
      (checkbox, avatar, badge, money formatting and row actions included)
      instead of being a bare set of cells.
    · Small actions got real behaviour too: data-demo-print opens the print
      dialog, data-demo-copy copies to the clipboard, data-demo-save and
      data-demo-discard persist a form in localStorage, data-demo-toggle flips a
      two-state button, data-demo-go follows a link, data-demo-gen runs the
      offline "AI" demo on the AI screens, data-demo-chat writes a message and
      an answer into the chat thread, and data-demo-export-row exports one row.

    · Dropdowns and menus are menus now, not decoration. The caret buttons in
      the page header, the card headers and the tables open a real Bootstrap
      menu; the 38 menu items that were href="#" placeholders became choices
      (data-demo-pick moves the tick, e.g. the AI model, the dashboard period,
      the analytics channel, the customer filter), actions with a confirmation
      toast, copy-to-clipboard items or links, so a menu never closes on
      nothing.
    · Pagination is generated from the rows, on every table that carries

      The four calendars filter the grid: the legend dots in the header and the
      switches in the sidebar are two views of the same state and always agree,
      the badge beside the title counts the events on screen, the sidebar says
      "Showing X of Y events", and switching everything off is met with an
      honest empty grid and a "Show all calendars" button instead of a blank
      table. A day with more than three events folds the rest into "+N more",
      which opens that day.
      "New event" opens a real dialog — title, date, time, end, calendar and
      place — with the same inline validation, announcements and undo the rest of
      the template uses: the saved event is drawn into the cell of the day it was
      given, its calendar is switched back on rather than swallowing it, and the
      chip is ringed briefly (never the whole card). Clicking any chip opens the
      event, where it can be edited (the form comes back filled, and the edit is
      announced and undoable) or deleted (also undoable). The demo events are
      seeded against the month the page opens on, so the calendar is never empty
      and "Today" always lands on a real day, whatever the date on the buyer's
      machine. assets/js/pages/calendar.js is 100% client-side; swapping the
      SEEDS list at the top of the file for your own data is the whole
      integration, and window.QevoraCalendar exposes events(), state() and
      refresh() for anything the markup does not cover.

    · The board filter panel and the header profile were the last two places
      where a narrow screen broke the design.
      The filter panel on pages/kanban.html keeps its desktop dropdown but no
      longer runs off the bottom of a phone: the panel is a column with a
      scrolling body (the three groups) and a pinned, opaque footer (the
      "Showing X of Y tasks" line and Clear), its width is capped against the
      viewport (½ the phone²s width at 320px, no horizontal scrollbar at any
      size) with 36px per chip on a phone, so the last row is reachable at any
      height. The panel stays anchored to the Filter button on every screen — a
      panel pinned to the bottom of a phone sits a thumb's journey away from the
      control that opened it — and it carries its own close button in the header
      ([data-demo-board-close]), so it can be dismissed without hunting for a
      piece of the page to tap. Closing it that way hands focus back to the
      Filter button. Give any panel the same classes and it behaves the same
      way; the structure is documented with the board hooks.
      The panel is also closed until it is asked for. Declaring its own display
      in the base rule overrode Bootstrap's hidden state: the panel was on
      screen the moment the page loaded, and it jumped into place on the first
      click, because Popper only positions a menu it is showing. Only the open
      panel (.dropdown-menu-filter.show) is a column now, so it opens where the
      Filter button is and closes on a click outside.
      The header profile button is a perfect circle below 768px (40px, no
      padding, centred avatar). It used to be a pill around the avatar: with the
      name and role hidden on a phone that left an oval ring hugging a round
      avatar. Avatars also carry aspect-ratio: 1 / 1 and a min-width per size, so
      a flex row that wants more width than it has can never stretch one into an
      oval either. On a phone the header is one even row: the drawer button, the
      colour mode, the notifications and the profile are the same 40px square
      with one optical icon size (the drawer glyph used to be 1.15rem against
      the 1.05rem of the buttons beside it), and every icon is centred by
      line-height instead of by baseline luck.

    · Every row of the products table in pages/products.html carried TWO Edit
      pencils: the actions cell had been edited twice, leaving a duplicate
      button (and on the AI Token Pack row the half-renamed copy still said
      "Edit AI Token Pack" while the row is "AI Token Pack — 1M"). Each row is
      now view / edit / delete once, the duplicated row keeps the name it
      actually has, and the table's static "Showing 1–5 of …" line counts the
      six rows in it. The audit grew two checks so this cannot come back: an
      actions cell may not hold the same control twice (the same icon doing the
      same job), and a control that names its row may not name a different one
      — "View AI Token Pack" on the "AI Token Pack — 1M" row is caught even
      though the two labels are not identical. Menu items inside a dropdown are
      left alone: the dashboard row legitimately offers "Message" both as a
      shortcut and inside its "…" menu.

    · Tapping the dimmed page behind an open drawer on a phone does nothing
      any more. The backdrop ships in the markup of every page, and sidebar.js
      only bound its click listener inside the branch that CREATES the element
      — so the listener was never attached on a real page, and the only ways out
      of the drawer were the Esc key and a navigation link. The click is bound
      once now, whether the backdrop was found or made.

    · Wide tables stay readable on a phone. A .table-responsive wrapper
      scrolls, but a table with no floor width still shrank to fit it: on
      pages/customer-details.html an invoice number wrapped over three lines, a
      date broke in two, and the last column was cut in half. Every data table in
      the package (all of them have four or more columns) now carries a floor and
      lets the wrapper do the scrolling — .table-min (40rem) at four or five
      columns, .table-min-lg (56rem) at six or more — with the first column kept
      on one line, because that is the one that identifies the row. Both floors
      only apply below 992px: on a desktop the table has room and nothing scrolls
      that did not scroll before. The pattern is documented on the Tables
      component page.
    · The phone header is opaque. It was a frosted strip at 85% opacity with a
      backdrop blur, which is a nice effect on a wide screen and a muddy one on a
      40px-tall row of controls: a card's gradient cover scrolling under it showed
      through between the icons. Below 768px the header uses the new solid
      --q-header-bg-solid token (white in the light palette, the sidebar ink in
      the dark one) and drops the blur; the desktop header is unchanged.

  Links, buttons and runtime behaviour
    · The light/dark toggle did nothing when localStorage is unavailable —
      private-mode windows, sandboxed frames and, most importantly, opening the
      template straight from disk (file://), which is exactly what a buyer does
      with the ZIP. The choice is now also held in memory, so the button always
      applies the theme for the session; the sidebar rail and the RTL switch
      share the same fallback.
    · Sortable table headers reordered the rows but never announced the sort
      state; the active column now carries aria-sort and the others are cleared.
    · The copy buttons read innerText, which needs layout — they fall back to
      textContent in embedded webviews where innerText is missing.
    · pages/projects.html — the "All / My projects" pills pointed at
      #projects-all and #projects-active, but no such panes existed, so clicking
      them did nothing. The grid is a real tab set now: every project, or the
      three Ava Reynolds is part of, with role/aria-controls wired up.
    · components/typography.html — "Change the font" linked to a #typography
      anchor the documentation page does not have; it points at the customise
      section that documents the font swap.
    · Every button in the template now carries an explicit type="button" (or
      type="submit" inside a form) instead of relying on the HTML default, which
      also stops a demo button from submitting a form it is dropped into.
    · Addresses printed as links are real mailto: links and the status link on
      the 500/maintenance pages is a real external link; the remaining
      placeholder menus keep href="#" and app.js already suppresses their jump.
    · Two audit checks cover this class of bug from now on: 18 validates every
      in-page anchor, cross-page anchor, data-bs-target and aria-controls, and
      19 requires an explicit button type and a real href on links.
    · All 82 pages were run in a scripted DOM smoke test (tools/smoke.mjs) —
      no console errors, no missing assets, no exceptions — and the same script
      clicks through the demo tabs, copy buttons, table sorting, pagination, a
      modal, the theme toggle, the collapsed-rail button and the chat composer.
      It ships in tools/; it is the only script that needs jsdom
      (npm install --no-save jsdom).

  Theme
    · Tooltips were unreadable in dark mode: the bubble colour was hardcoded to
      a dark navy while Bootstrap derives the tooltip text colour from
      --bs-body-bg, which is #0b0f1c in this palette — dark text on a dark
      bubble, measured at 1.05:1. Both colours are now tokens
      (--q-tooltip-bg / --q-tooltip-color), so dark mode shows Bootstrap's
      familiar inverted bubble (light surface, dark label) and the light theme
      is unchanged.
    · The audit gained a theme pass that resolves the token cascade of both
      themes and measures real WCAG contrast for tooltips, cards/popovers,
      dropdown menus, modal dialogs and toasts — the failure above would have
      been caught by it (it reports 1.05:1 for the old bubble).

  Shell — collapsed sidebar
    · Clicking a section icon in the collapsed rail used to open a fly-out
      submenu panel, but the navigation column is a scroll container
      (overflow-x: hidden), so the panel was clipped to the width of the rail
      and all the reader saw was an empty white sliver. The rail no longer opens
      a panel at all: a click expands the sidebar and opens that section, and
      hovering shows the section name as a tooltip.
    · The 78px icon rail used to hold both the brand mark and the inline
      collapse button, so the two overflowed the rail and the logo was clipped
      against the left edge. The rail now centres the mark on its own and the
      inline button steps aside: the header button collapses and expands the
      sidebar (it is now labelled "Expand navigation" / "Collapse navigation"
      and swaps to a chevron while collapsed).
    · Compact labels were hidden with display:none, which stripped the
      accessible name from every icon-only link and left the fly-out submenus
      showing empty rows. Labels are clipped instead of removed, the submenu
      popovers show their text again, and each rail icon gets a tooltip on
      hover or focus.
    · Both sidebar togglers now report aria-expanded together, and tooltip
      instances are created through getOrCreateInstance so no duplicate
      Bootstrap instance is ever registered.

  Core and design system

      .bg-accent. All four are now shipped as utilities.
    · .kanban__col-body — the drag & drop target handled by components.js —
      had no styling; it now has a minimum height so empty columns stay usable.
